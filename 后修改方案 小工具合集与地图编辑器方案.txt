本文只提供实施方案，不修改游戏工程数据。

仓库：D:\Documents\GitHub\yami-tools

GitHub Pages：https://bajibaji.github.io/yami-tools/

二、重要结论（v2 已核实）
-------------------------

1. 现有 Excel 数据链路（保持为数据源）：

   读取excel.3739667372fedf5f.event
     → 读取 地图格.34eee41059f43f30.xlsx
     → 工作表 1：名称
     → 工作表 2：等级区间
     → 工作表 3：图标
     → 工作表 4：通行状态
     → 工作表 5：刷怪列表
     → 写入五个全局对象变量

2. 输出格式改为单一二维数组后，五个旧全局数组不再作为主数据，但保留为兼容拆分目标（见第七章路线 A）。

3. 通行方向映射（已核实 UI 事件）：

   大地图.c08c259efa227757.ui 中，通行字符串先 split(",")：
     lineX = 第一位（index 0），lineX == "1" 时创建横向连线预设 d0818b8a6779c8d8；
     lineY = 第二位（index 1），lineY == "1" 时创建纵向连线预设 411c7118c9602ba9。

   迁移规则（写进新 JSON）：

     旧 "0,1"  →  Passability = { "down": true,  "right": false }
     旧 "1,0"  →  Passability = { "down": false, "right": true }
     旧 "1,1"  →  Passability = { "down": true,  "right": true }

   即：第一位 → right（向右通行），第二位 → down（向下通行）。

4. 运行时寻路数据与连线数据是两套数据，不要混淆：

   - Excel 工作表 4（通行状态，"0,1"）→ 地图连线渲染（大地图 UI 消费）。
   - 地图通行数据.9e8282a5917c31db.json（cols/rows/grid 0-1 矩阵 + blockedEdges）→ 寻路/通行判定。
   - 新格式的 Passability 只对应前者（连线）。寻路数据文件不在本方案改造范围。

5. 等级数据迁移：

   - 旧等级区间表是“每格一个区间”（如 5～30、60～70）。
   - 新格式把等级放进了每个怪物（lvMin/lvMax），但存在 32 个格子有等级区间而刷怪列表为“-”（无怪物）。
   - 决策：每格保留可选 levelRange（{ min, max }），保住这 32 个格子的等级显示；同时每个怪物仍带自己的 lvMin/lvMax（迁移时默认取该格区间，编辑器可细调）。

6. 刷怪数据迁移（已确认 Excel 格式保持不变）：

   - 刷怪列表表保持现状：单元格为逗号分隔的 16 位 hex GUID，或 “-”（无怪物）。
   - 导出时：每个怪物的 lvMin/lvMax 取该格等级区间，weight 默认 1；
     怪物等级/权重的细化通过可视化编辑器完成。
   - 已确认当前 Excel 中的刷怪 GUID 均有效（对应 .actor 存在）。

7. 运行时生效前提：

   新字段（monsters 的 weight / lvMin / lvMax）只有在 Yami 端改造刷怪算法后才会生效；
   若旧地下城刷怪事件仍按“逗号拆 GUID”取怪，则 weight 与等级不会起作用（见第七章路线 B）。

8. 网站工具全部在浏览器本地处理 Excel 与 JSON，不上传服务器。

四、新 JSON 格式（核心）
-----------------------

4.1 根结构

   输出文件根节点就是二维数组（真实导出为 10 行 × 10 列）：

   [
     [ { ... }, { ... }, ... 10 列 ],
     ... 10 行
   ]

   - 不包 { version, rows, cols } 外壳：运行时加载最直接，行列数由数组本身确定。
   - 如需元数据（可选，不在 MVP）：伴生 地图格数据.meta.json（版本、来源文件名、工作表名），
     运行时可忽略。

4.2 单元格 Schema

   {
     "name": "边境哨所",            // string：地点名称；无名称用 ""
     "icon": 3,                     // integer：地形图标；-1 = 不可用/空地；0 和正整数是图标类型
     "Passability": {               // 可通行性（沿用用户指定命名）
       "down": false,               // boolean：是否可向下通行
       "right": true                // boolean：是否可向右通行
     },
     "levelRange": {                // 可选：该地点等级区间（保留旧等级表信息）
       "min": 5,                    // integer >= 1
       "max": 30                    // integer >= min
     },
     "monsters": [                  // 刷怪数据列表；无怪物时为空数组 []
       {
         "id": "d4bf5e107664f5c1",  // string：16 位 hex，对应 Assets 下 .actor 文件
         "lvMin": 5,                // integer >= 1：可能的最小等级
         "lvMax": 30,               // integer >= lvMin：可能的最大等级
         "weight": 1                // number > 0：出现权重
       }
     ]
   }

   字段命名约定（严格）：

   - name、icon、Passability、monsters、levelRange、id、lvMin、lvMax、weight 大小写固定，
     编辑器与加载器均按此解析。
   - Passability 的子字段固定为 down / right（小写）。

4.3 字段规则

   name：string；无名称用空字符串 ""（不用 null）。

   icon：integer；-1 表示不可用/空地；0 和正整数是图标类型，不能错误视为“空”。

   Passability：{ down: boolean, right: boolean }；
     down = 向下（第二格）通行，right = 向右（第二格）通行；
     不可通行格子的默认值 { down: false, right: false }。

   levelRange：可选对象 { min, max }，均为正整数且 max >= min；
     允许只写怪物等级而不写 levelRange（此时该格不显示等级区间）。

   monsters：数组，元素 { id, lvMin, lvMax, weight }；
     id 必须为 16 位十六进制；
     lvMin >= 1，lvMax >= lvMin；
     weight > 0（同一格内多个怪物权重共同参与加权随机；权重为 0 视为禁用该怪，校验时不阻止但提示）；
     同一格内怪物 id 不允许重复。

   空单元格约定：

   {
     "name": "",
     "icon": -1,
     "Passability": { "down": false, "right": false },
     "monsters": []
   }
   （无 levelRange 字段）

4.4 示例 JSON（2×3 缩略示意，真实导出为 10×10）

[
  [
    { "name": "边境哨所", "icon": 3, "Passability": { "down": false, "right": true }, "levelRange": { "min": 5, "max": 30 }, "monsters": [ { "id": "d4bf5e107664f5c1", "lvMin": 5, "lvMax": 30, "weight": 1 } ] },
    { "name": "芦苇平原", "icon": 1, "Passability": { "down": true, "right": true }, "levelRange": { "min": 60, "max": 70 }, "monsters": [ { "id": "421b5f9cee70b119", "lvMin": 60, "lvMax": 70, "weight": 1 } ] },
    { "name": "", "icon": -1, "Passability": { "down": false, "right": false }, "monsters": [] }

    { "name": "狂风山道", "icon": 5, "Passability": { "down": true, "right": false }, "levelRange": { "min": 60, "max": 70 }, "monsters": [] },

五、Excel 导入与映射规则（五表 → 单数组合并）
--------------------------------------------

5.1 工作表映射

   工作表 1：名称         → 单元格 name
   工作表 2：等级区间     → 单元格 levelRange（min/max），并作为该格怪物默认 lvMin/lvMax
   工作表 3：图标         → 单元格 icon
   工作表 4：通行状态     → 单元格 Passability（第一位 → right，第二位 → down）
   工作表 5：刷怪列表     → 单元格 monsters[].id（weight 默认 1）

   五个全局对象变量不再作为主输出（原 ID 仅用于路线 A 兼容拆分）：
     地图名称      b266af08c47fc3b4
     地图等级分布  c13d5157ada76039
     地图icon分部  6fb261049614e47c
     地图icon连线  baf6c5f5164a98cf
     地图刷怪列表  9dadd844e12cb6cb
   旧 Excel 工作簿 Promise 全局变量（excel表格 973b33fc7fdbd926）在 JSON 模式下不再需要。

5.2 迁移规则

   等级区间：
     - "5～30"、"5-30"、"5~30" 均解析为 { min: 5, max: 30 }，导出统一为怪物的数字 lvMin/lvMax；
     - levelRange 保留原区间；
     - 区间为 0 或空 → 不写 levelRange，怪物 lvMin/lvMax 回退为 1；
     - 32 个“有等级但无怪物”的格子：仅写 levelRange，monsters 为空数组。

   刷怪列表：
     - "-" → monsters: []（保留原样，不转换为 null）；
     - "d4bf5e107664f5c1,421b5f9cee70b119" → 两个怪物条目，lvMin/lvMax 取该格区间（缺省 1），weight 默认 1；
     - GUID 必须为 16 位十六进制，否则报错定位到单元格。

5.3 10×10 标准化（沿用 v1 规则）

   - 真实有内容的范围固定为 10 行 × 10 列；地图 UI 也按 10×10 消费。
   - ExcelJS 会把格式残留算入 rowCount（真实五表被格式撑到 200 行，名称表 12 列）。
   - 导出器强制 rows = 10、columns = 10：
     1. 只允许裁剪第 11 行以后、第 11 列以后全部为空的区域；
     2. 裁剪时显示警告，例如：
        “检测到 Excel 格式残留：名称表报告为 200×12，实际内容为 10×10，已安全标准化。”
     3. 第 11 行以后或第 11 列以后存在真实值时，阻止导出；
     4. 10×10 内缺失单元格必须补 null（对应空单元格对象）；
     5. 不允许 filter(Boolean)、trim 空行、压缩行列，否则地图坐标会错位。

5.4 校验规则（沿用 v1 并扩展）

   名称表：string 或空。
   等级区间表：null、数字 0、或字符串（5-30 / 5~30 / 5～30）。
   图标表：整数；-1 表示不可用；0 和正整数有效，不能视为空。
   通行状态表：null 或 "0,0" / "0,1" / "1,0" / "1,1"。
   刷怪列表表：null、"-"、或逗号分隔的 16 位 hex GUID。
   扩展校验：
     - 怪物 lvMin/lvMax 解析后必须 1 <= lvMin <= lvMax；
     - 同格怪物 id 去重校验；
     - 可选：选择游戏工程目录后，校验怪物 GUID 对应 .actor 文件是否存在。

   禁止导出：Excel 公式、日期、错误值、富文本、超链接对象（定位单元格报错）。


六、可视化编辑（新功能）
-----------------------

6.1 工具定位

   工具更名为“地图编辑器”，页面默认直接进入实际工具，不做介绍型落地页。
   三大入口（顶部切换）：
   1. 导入 Excel：选择/拖入 地图格.xlsx → 按第五章规则解析 → 进入编辑态；
   2. 导入 JSON：选择/拖入已导出的地图 JSON → 直接进入编辑态（可继续修改）；
   3. 新建：生成 10×10 空网格 → 从零编辑。

6.2 界面组成

   1. 文件选择/拖放区（.xlsx 与 .json 均支持）。
   2. 工作表映射区：显示五张表识别结果与警告。
   3. 10×10 网格画布：
      - 每格显示图标（图例配色）、名称（截断）、通行连线（右/下边缘高亮）、刷怪标记；
      - 点选格子高亮，可多选（Ctrl/Shift）。
   4. 侧栏编辑表单（当前选中格）：
      - 名称（文本）；
      - 图标（图例选择器，含 -1 空地、0、各图标类型）；
      - 向下通行 / 向右通行（开关）；
      - 等级区间（可选 min/max）；
      - 刷怪列表：增删行，每行 id（GUID 输入 + 校验）、lvMin、lvMax、weight；
        （可选）选择游戏工程后提供 .actor 名称补全。
   5. 错误与警告列表（定位到 行/列/单元格）。
   6. JSON 预览区（只读，随编辑实时更新）。
   7. 下载 JSON 按钮（导出为 地图格.json）。

6.3 编辑行为约定

   - 任何编辑都作用于内存模型（二维数组），未导出前不产生文件。
   - 空单元格对象按 4.3 约定补齐，不产生 undefined 字段。
   - 图标 0 与 -1 必须可区分（0 是合法图标类型）。
   - 怪物权重支持小数；weight 为 0 时提示“该怪将被禁用”。
   - 校验错误时禁止导出（或导出前强制确认）。

6.4 导出

   - 导出内容与第四章 Schema 完全一致；
   - 导出文件名默认 地图格.json；
   - 文件下载在浏览器本地完成，不上传服务器。


七、Yami 运行时的 JSON 加载方案（v2 更新）
-----------------------------------------

7.1 新增自定义指令：地图JSON读取.指令.ts

   - JSON 建议放在：Assets/UI/地图/地图格数据.<新GUID>.json，并登记到 Data/manifest.json 的 others 资源中。
   - 指令职责：
     1. 读取 JSON（兼容 Electron/编辑器 fs.readFileSync 与发布浏览器 fetch(Loader.route(...)) 两种环境）；
     2. 校验：完整校验二维数组 10×10、每格字段类型、monsters 合法性；
     3. 全部通过后一次性写入全局变量，验证失败不写任何数据（避免地图半更新）。
   - 主数据写入一个全局对象变量（建议：地图格数据，新 GUID 在实施阶段生成），
     值为 root 二维数组本身。

7.2 路线 A：旧地图 UI 兼容（不改地图 UI 事件）

   - 地图 JSON 读取指令在写入主变量后，可同时把数据拆分为旧五数组，
     按第五章列出的五个旧全局变量 ID 写入，保证现有 大地图 UI 与五个回调事件的消费逻辑不变。
   - 旧连线逻辑（lineX/lineY → 横向/纵向连线预设）等价于新 Passability 的 right/down，
     拆分时按“第一位 → right、第二位 → down”反向生成 "0,1" 字符串即可。
   - 运行时寻路数据 地图通行数据.9e8282a5917c31db.json 不在本方案改造范围。

7.3 路线 B：刷怪算法改造（让新字段生效）

   - 旧地下城刷怪事件目前按“逗号拆 GUID”取怪，weight / lvMin / lvMax 不会生效。
   - 改造刷怪算法：从地图格数据的 monsters 列表按 weight 加权随机选怪，
     再在 lvMin ~ lvMax 区间内随机生成怪物等级。
   - 改造对象为调用地图格数据的刷怪/遭遇事件；改造前旧逻辑保持可用。

7.4 统一入口与兼容

   - 统一入口事件 读取excel.3739667372fedf5f.event 必须继续保持原 GUID：
     以下两个事件已经调用它：@5 新的游戏.40b2ca62601a61b7.event、@6加载存档.e4b32024ea7435a1.event。
   - 迁移做法：
     1. 保留读取excel事件文件和 GUID；
     2. 内部改为调用 地图JSON读取 指令（移除 Excel read/to-array 链）；
     3. 地图JSON读取 按路线 A 拆分写入五个旧变量（兼容），并按路线 B 提供刷怪数据结构；
     4. 原五个 Excel 回调事件先保留，作为开发期/回滚兼容；确认稳定后再清理。
