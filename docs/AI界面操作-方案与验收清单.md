# AI 界面操作方案（方案确认稿）

> 目的：把「AI 助手」从"在后台改文件"升级为"**在 Open Yami 界面上一步一步地操作，全程让用户看得见**"。
> 状态：**十条决策已与用户逐条确认定案**，本文档只描述要做什么与怎么验收，不含实现代码。
> 读者：实现方 + 验收方。

---

## 0. 一句话定位

小白用户在编辑器里干活，停在某个东西上，用一句话让 AI 接手；AI 先跟用户对齐"你到底要什么"，对齐完**自动开工**，每一步都在界面上用**收束边框**指给用户看，随时可以打断。

## 1. 已定案（十条，逐条与用户确认过）

| # | 决策 | 定案 |
| :--- | :--- | :--- |
| 1 | AI 的"手" | 走**引擎公开入口**（"假装点了"即可），不做真实鼠标模拟点击。效果是编辑器界面自己跟着变 |
| 2 | 可见性（硬指标） | **高亮边框线，从大收束到"即将被操作的那个元素"的边框上**；动手前指，停一拍再动 |
| 3 | 危险分级 | 绿=自动演自动做（附「撤销这一步」）／黄=停下来点头／红=打字确认／`cdp_eval` 默认关闭 |
| 4 | 撤销必须是真的 | 改属性必须补 `focus() -> 写值 -> blur()`，否则引擎不写撤销栈（硬前置，见 4.1） |
| 5 | 盲区必修 | 见第 4 节，八条全部必修 |
| 6 | 开工前对齐 | **必须先确认用户到底要什么**，不许自作主张开工；对齐完一口气自动干完；全程可打断 |
| 7 | 对齐卡形态 | **一次问清（选择题）**；**不设问题数量上限**——判据是"这一问的答案会不会改变我接下来的做法"，会才问，不会的一律不许问 |
| 8 | 接入方式 | **甲：不改入口**。用户照旧打开面板说需求，AI 靠环境感知知道他在哪 |
| 9 | 视野可见 | **丙：常显上下文行 + 不确定必须反问**（因为第 8 条把"猜"变成了唯一上下文来源，必须可纠错） |
| 10 | 能力范围 | **乙：数据类全套；脚本改动保留能力但不进界面演出**（无落点，演不出来） |

## 2. 演出规格（节奏已定案）

单个动作时间轴，**总计 1.0 秒**：

| 时间 | 环节 | 说明 |
| :--- | :--- | :--- |
| 0 -> 240ms | **收束** | 边框从外扩 28px 收到元素边框上 |
| 240 -> 580ms | **停留** | 预告："就是这儿" |
| 580ms | **执行** | 瞬时（引擎入口是毫秒级） |
| 580 -> 1000ms | **留痕** | 同一个框变色（预告=蓝，已改=绿），不新增元素 |

**合并规则**（否则批量改会变成慢动作回放）：

- 同一目标的一批改动算**一步**：边框先在该目标收束一次（"我要改这个的 3 个地方"），然后各落点**快速依次点过（每个 120ms，不停留）**，最后一次留痕。
- 一步最多指 **5 个落点**，超过折叠为"…还有 N 处"，全清单放卡片。
- 提供**「别演了」**跳过按钮：直接跑完，用结果卡片交代。
- **用户在动，演出让路**：检测到用户正在打字/点击 -> 暂停演出（同时规避抢焦点）。
- **用户看不见时不空转**：编辑器最小化或切走 -> 直接跑完，回来给"刚才做了什么"清单。

**技术选型（避免走弯路）**：

- 边框用 `outline` + 动画 `outline-offset`（+28px -> 0）：线宽恒定（用 `transform: scale` 会把边框一起缩放粗细，很丑），且**不触发重排**。
- 位置用 `transform: translate()` 跟随目标 `getBoundingClientRect()`，**不要写 top/left/width/height**。
- 浮层必须 `pointer-events: none`，只在"别演了"按钮上恢复事件；z-index 与现有 `#yami-perf-dock` / `.yami-perf-toast` 体系对齐。
- 动画期间目标可能被滚动/重建/裁切：必须**每帧或按 scroll/resize 重新取 rect**；取不到就按 5.5 如实停下。
- keyframes / class 名加命名空间前缀，避免与编辑器样式冲突。
- 编辑器是 WebGL 重负载应用，**我们自己就是性能插件，不许在编辑器里制造 layout thrash**。
- **第一版不演画布对象**（角色/光源/触发区域在 WebGL 画布上没有 DOM 节点，挂不上框）。第一版只演面板、列表、输入框这一层。

## 3. 能力范围与危险分级（对应决策 10）

| 活 | 界面落点 | 档位 | 演不演 |
| :--- | :--- | :--- | :--- |
| 定位/查看资源、看懂现状 | 资源树、检视器 | 绿 | 演 |
| 改属性/数值（攻击力、血量、坐标…） | 检视器输入框 | 绿 | 演 |
| 装配事件指令（加对话、演出、逻辑） | 事件编辑器 | 黄 | 演 |
| 新建 / 复制资源（照现有改） | 资源树 | 黄 | 演 |
| 删除资源 | 资源树 | 红（打字确认） | 演 + 先备份 |
| 跑试玩、看报错、给结论 | 标题栏试玩键 | 绿 | 演 |
| 批量改（一次 3 处以上） | 多个落点 | 黄（先给清单） | 演，合并成一步 |
| 改脚本 / 自定义指令 | **无落点** | 黄 | **不演**，卡片交代"改了哪个文件、改了什么" |

分级判据是**"能不能一键撤回"**，不是拍脑袋：

| 手 | 现有安全网 |
| :--- | :--- |
| 只读类 | 无风险 |
| 界面导航 | 无风险，随时手动点回去 |
| 改属性值 | **需补 focus/blur 才进撤销栈**（4.1） |
| 改脚本 / 补丁资源 / 加指令 | 默认 `dryRun` 预览、`expectedSha256` 防覆盖 |
| 删资源 | 删前自动备份到 `.yami-mcp-backups` |
| 任何写盘 | 有备份 + `list_backups` / `restore_backup` + `project_changelog` |
| `cdp_eval` | **无任何安全网**，能执行任意 JS -> 默认关闭，小白界面不出现 |

**黄/红档复用现有审批卡**：`ai-host.js:1781`（`FILE_MUTATIONS` / `DELETE_TOOLS` / `approvalMode`）+ 面板 `#yami-ai-approval`。
注意区分：**开工前的"对齐卡"是新的东西**，它对齐的是**意图**，不是某一次写操作。

## 4. 必修盲区（八条，全部已确认必修）

### 4.1 撤销栈：改属性现在根本没进撤销栈（硬前置）

- 引擎把检视器改动记进撤销栈靠 **blur**：`inspector.ts:340` `Inspector.inputBlur`，各页面绑 `elements.on('blur', ...)`（如 `file-scene-page.ts:56`）。
- AI 只"设值 + 派发 input/change"不触发 blur 时，`manager.focusing === null` -> **直接 return，什么都不记**，用户 Ctrl+Z 撤不回来。
- 要求：走检视器入口改值时补 `focus() -> 写值 -> blur()`；并保证用户原本的焦点与未提交输入不被破坏（见 4.5）。

### 4.2 "用户在哪一页/哪个窗口"根本没采集

- 权威字段 `Layout.manager.index`（`layout.ts:123/266`），取值 `home / directory / project / scene / ui / animation / particle` 等。
- 现环境感知**一个字段都没读它**：用户停在数据表/动画/界面页时，AI 只知道上次打开的场景名 -> 会指着错的地方说"我改这个"。
- 动画窗口 / UI 窗口 / 粒子窗口是**浮动窗口**，不在 `Layout` 里，需单独判"当前焦点窗口"。
- 附带修正上轮已知缺陷：检视器名要从 `Inspector.meta.file.alias`（或 `.name`）取，`FileMeta` 没有 `name/alias`；场景对象类型要用 `Scene.target.class`（`scene-target.ts:17`），不是 `.type`；`Game.running` 在引擎里不存在，试玩态要另行判定。

### 4.3 AutoReload 会吃掉用户正在敲的输入（真竞态）

- 引擎保护是 `autoreload.ts:157` `Data.manifest.changes.includes(meta)`，但该集合**只在 blur 之后**才登记（3.1）。
- 因此：用户正在输入框里敲字、尚未失焦 -> AI 此时写盘 -> 引擎认为"无未保存改动" -> 重载并重新 open 面板（`autoreload.ts:204-211`）-> **用户敲了一半的内容被冲掉**。
- 要求：AI 的手**统一走界面入口**；必须写盘时先检查"当前是否有未失焦的输入"，有则排队等待或明确告知用户。

### 4.4 双编辑器实例 = 操作到另一个工程

- 端口写死：`BRIDGE_PORT = 5966`、`editorServer.listen(5967)`；`EADDRINUSE` **被静默吞掉**（`probe-core.js:3624-3626`）。
- 开第二个编辑器（另一个工程）时它没有桥，AI 的每条命令都打到**第一个工程的编辑器**上；而 MCP 文件工具按 `YAMI_PROJECT_ROOT` 走 -> 一半的手动这个工程、一半手动那个工程，**用户完全看不出来**。
- 要求：端口占用必须**如实识别并告知**（"检测到另一个编辑器实例占用，请确认我在操作哪个工程"），绝不允许静默错配。

### 4.5 抢焦点 / 踩掉用户正在输入的内容

- 引擎自己就会：`Inspector.open()` 里 `document.activeElement.blur()`（`inspector.ts:202-204`）——这个 blur 还会**触发 history.save 把用户敲了一半的值提交掉**。
- 再加上 4.1 要求补的 `focus()/blur()`，两边都会踩。
- 要求：目标已聚焦就不补；动作前记住原焦点并还回去；**用户正在输入时排队等待**。

### 4.6 演到一半出事 + 演得太慢

- 目标找不到（引擎升级改了 DOM、元素被 `overflow:hidden` 裁掉、列表重建把它卸载）-> **必须如实停下说清楚，不许继续瞎点**（建议钉成铁律）。
- 全局急停：面板「停止」+ 编辑器内快捷键，**停在两个动作之间**；停下后必须告知"已做到第 N 步、改了这 M 个地方"，并给 `[全部撤回]` / `[保留已做的]`。
- 现有底子：面板开着且正忙时 `Esc` 已经是停（`ai-agent.js:2248-2257`），升级即可。

### 4.7 浮层技术坑

见第 2 节"技术选型"（rect 跟随、不重排、命名空间、面板可能遮挡目标）。

### 4.8 发现性与控件表漂移

- 发现性：靠决策 9 的**常显上下文行**补偿（小白看到"选中「木剑.item」"就明白 AI 看得见他在干什么）。
- `dumpUi` 的控件选择器表是靠 DOM 特征写死的，**引擎一升级就可能失效**（本轮就抓到 `page-frame` 没有 id、页面用 CSS 类 `visible` 切换而非 inline style 两个反例）-> 失效时必须降级为"找不到"，不许乱指。

## 5. 交互形态

### 5.1 开工前：对齐卡（决策 6/7）

用户说"把木剑做强一点"，AI 回一张卡（示例）：

> 我理解你要：**让「木剑」更强**
> 请拍两件事：
> ① 强到什么程度？ -> `稍微强一点` `明显变强` `强到夸张`
> ② 顺带改说明文字吗？ -> `只改数值` `顺便改说明`
> 其余我按默认来（不动图标、不改名字、不动已有指令）
> 　`[ 开工 ]`　`[ 我再补充 ]`

约束：

- **只问"答案会改变接下来的做法"的问题**（决策 7）。凑数的、走过场的、有默认值也行的一律不许问。
- 问几问由"有多少真歧义"决定，**不设上限**。
- 答不到的信息要能"让用户在界面上指出"（小白说得清"哪个"最简单的方式是指一下）。
- 除了问，其余按默认并在卡里**明写出来**，用户可当场否决。
- 对齐完 AI 回一句开工回执（"好，我这就来：① ② ③，边做边给你看"）-> 立刻开演。

### 5.2 开工后：演出 + 打断

- 每步按第 2 节时间轴演；黄档停在审批卡；红档打字确认。
- 打断见 4.6。

### 5.3 面板常显上下文行（决策 9）

- 面板顶部固定一行：`场景「新手村」· 选中「木剑.item」· 检视「木剑」`（具体字段随环境感知能力）。
- 切页面/换选中后应及时更新；点它可纠正/清空。
- **AI 自己不确定时，必须反问**，不许硬猜。

## 6. 验收清单（可证伪，交付时逐条验）

### 6.1 演出与可见性

1. 边框 1:1 贴合目标：脚本读取浮层 rect 与目标 `getBoundingClientRect()` 比对，误差 <= 1px。
2. 时间轴：单动作从收束开始到留痕结束 <= 1.05s（计时断言）。
3. 批量 3 处合并为一步，总时长 <= 1.4s，且落点数不超过 5。
4. 边框不遮挡操作：浮层命中测试返回 `pointer-events: none`；用户点击能穿透到编辑器控件。
5. 演出期间编辑器帧耗时无恶化（用 5966 `/live` 采样对比，或 `tests/test-render-perf.cjs`）。
6. 目标被滚动/重建/裁切时，边框不留在错误位置；取不到目标时**如实停下**，不许继续执行后续动作。

### 6.2 撤销与安全

7. 改属性后 `UndoManager` 可撤销，且撤销后值回到原值（真机断言）。
8. 绿档动作完成后，面板出现可用的「撤销这一步」。
9. 黄档动作必须停在审批卡，未点头不得执行（构造用例）。
10. 红档删除必须打字确认；删后有「恢复」入口，且 `.yami-mcp-backups` 里确有备份。
11. `cdp_eval` 在小白默认配置下**不可达**（工具列表里不出现）。

### 6.3 盲区（第 4 节逐条对着验）

12. 4.2：切到 `directory / animation / ui` 等页面后，上下文行 1 秒内正确反映"当前在哪一页"。
13. 4.2：检视器名、场景对象类型、试玩态三个字段在真机上取值正确（用引擎真实字段形状构造，不许只做字符串存在性断言）。
14. 4.3：用户正在输入未失焦时，AI 不得写该文件（排队或告知）。
15. 4.4：开第二个编辑器实例时，必须如实识别端口占用并告知，不得静默操作错工程。
16. 4.5：AI 动作前后，用户原本的焦点与未提交输入仍在（断言 DOM 焦点与值）。
17. 4.6：急停停在动作之间；停后给出"已做步骤 + 改动清单 + 撤销入口"。
18. 4.8：把控件表故意打坏（改一个 id），AI 必须报"找不到目标"并停下，不许乱指。

### 6.4 对齐与反问

19. 需求模糊时必须出对齐卡；需求明确无取舍时不许问凑数问题（各给一组测试语料）。
20. 答不出关键信息时，AI 必须反问或请用户在界面上指出，不许硬猜（构造环境感知缺失场景）。

### 6.5 不回归

21. `node build.cjs` 全绿（46 核心锚点 + 10 整包锚点 + 0 Emoji + 术语合规 + 滚动条单一事实源 + 文档一致性）。
22. `node tests/run-all.cjs` 不低于当前基线 25/28。
23. 生产镜像 `--deploy` 后逐文件 MD5 一致。

## 7. 第一版明确不做（避免范围蔓延）

- 不做真实鼠标模拟点击（决策 1）。
- 不演画布对象（角色/光源/触发区域），第一版只演面板/列表/输入框。
- 不演脚本改动（无落点），只用卡片交代。
- 不在编辑器里新增"接入入口"（不气泡、不快捷键，决策 8）。
- 不开放 `cdp_eval` 给普通用户。

## 8. 上游依赖（不修就不要开工）

本轮验收已确认环境感知存在三处硬缺陷（检视器名恒空、场景对象类型恒错、试玩态恒假）与一处误报风险（试玩窗口会被报成"编辑器"）。

**截至 `cd001ac V1.5.3` 的修复现状（已逐条核对代码）**：

| 缺陷 | 状态 | 证据 |
| :--- | :--- | :--- |
| 检视器名恒空 | **已修** | `probe-core.js:1943-1948` 改为 `meta.file.alias \|\| meta.file.name`，与引擎 `FileMeta` 真实结构一致 |
| 场景对象类型恒错 | **已修** | `probe-core.js:1959` 改为 `tgt.class \|\| tgt.type \|\| 'object'`，与 `scene-target.ts:17` 一致 |
| 试玩态恒假 | **仍未修（换了个写法但依然恒假）** | `probe-core.js:1904` 判据是 `!isEditorHostPage && typeof Game.update === 'function'`；而 `/context` 只挂在 5967（`probe-core.js:3446`），5967 的启动闸门是 `if (!isEditorHostPage) return`（`probe-core.js:3402`）。**两者互斥**：能应答 `/context` 的页面必然 `isEditorHostPage === true`，于是 `isPlaytest` 恒为 false，`environment` 恒为 `'editor'` |
| 试玩窗口被报成"编辑器"（误报事实） | **仍未修** | 用户在试玩窗口里提问时，宿主查的仍是编辑器页的 5967，拿回编辑器快照并标注"编辑器"——这不是"未知"，是**注入错误事实**。5966 桥（`probe-core.js:3346`）只有 `/live /report /diagnose /stream`，**没有 `/context`** |

**结论：试玩这一条必须先修好**（两选一）——

1. 让 5966 桥也暴露 `/context`，并让宿主能区分"这个 5966 是谁占的"；或
2. 更可靠：`probe-core.js` 与 `ai-agent.js` 同在 MAIN world，由 probe-core 暴露一个页面内全局钩子（如 `window.__YAMI_CTX__`），面板发 `/chat` 时把 `{ page: 'editor' | 'playtest', summary }` 一起带给宿主，宿主优先用面板送来的这一份——**谁在提问，就用谁的视野**，不靠端口猜。

否则第 4.2 与 5.3 都无从谈起。
