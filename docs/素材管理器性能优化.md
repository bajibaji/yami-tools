# 素材管理器 Pro · 性能优化记录（2026-08-28）

> 现状：全库约 11 万文件（D:\YAHZJ\技能素材）。本记录列出本次代码审查发现的卡顿根因、已做的优化与预期收益，以及后续可再做的项。

## 一、审查发现的卡顿根因（按严重度）

1. **搜索每次按键全库 IDB 光标扫描**：`dbSearchFiles` 每按一个字符就 openCursor 扫 11 万条，且无防抖、无过期请求丢弃，快速输入时多路并发叠加 → 明显卡顿。
2. **左侧目录展开 DOM 爆炸**：unTied Games 等包有几千个叶子目录，`p.dirs.map` 全部渲染成按钮 → 展开即卡死。
3. **PreviewPane 无缓存**：切换动画每次都重新 entryBlob + createImageBitmap 解码；来回切换反复解码，且旧解码不取消。
4. **长序列串行解码**：单帧动画逐帧 await createImageBitmap，30 帧动画约 1s 才能播。
5. **目录/包查询上限过低**：`dbQueryByIndex(..., 250/300)` 只取前 250-300 条，且快速切换目录时旧结果覆盖新结果（竞态）。
6. **缩略图**：每张缩略图单独开一个 IDB 写事务（频繁滚动时事务风暴）；内存缓存仅 150 个，滚动浏览时反复生成。
7. **表格行/列表组件引用不稳定**：`renderTableRow` 每次渲染新建，VirtualList 无法 memo 复用。

## 二、已实施优化（本地构建通过）

| # | 优化 | 位置 | 预期收益 |
|---|---|---|---|
| 1 | 搜索防抖 250ms + **一次性内存搜索索引**（扫描/恢复后从 IDB 建 11 万条轻量数组，搜索纯内存 filter） | AssetManagerPage | 搜索从"每次按键扫全库光标（数百 ms~秒级）"→ 输入停顿 250ms 后 ~5ms 出结果 |
| 2 | 子目录**分页渲染**（默认 60 个 + "显示更多"每次 +120） | AssetManagerPage explorer | 展开几千目录的包不再 DOM 爆炸 |
| 3 | 预览数据 **MRU 缓存**（LRU 8 个动画，淘汰时 close ImageBitmap） | comps.jsx | 来回切换动画 0 解码；内存有界 |
| 4 | 序列帧**并发 4 路解码** | comps.jsx decodeFrames | 30 帧动画解码时间约 1/4 |
| 5 | 过期请求令牌（loadReqRef）+ 包/目录查询上限提到 3000 | AssetManagerPage loadDirectoryData | 快速切换目录不再被旧结果覆盖；单次可载入更多动画 |
| 6 | 缩略图**并发 3 + IDB 批量写（300ms 合并事务）+ LRU 300** | thumb.js | 滚动缩略图不再事务风暴，内存可控 |
| 7 | **VirtualList memo + renderTableRow useCallback** | comps.jsx / AssetManagerPage | 表格视图滚动不再每帧重建行 |
| 8 | 卡片悬停 GIF 预览 **LRU 缓存（64）** | comps.jsx GalleryCard | 浏览画廊时内存稳定 |
| 9 | 换库/重扫时重置搜索索引 | AssetManagerPage runStreamScan | 不同素材库不串数据 |

## 四、后续可再做的项（本次未做/可选）

1. **包级全量浏览上限**：单包 >3000 文件时目前仍截断（可继续点子目录更精确）；如需包内无缝全览，可把 pack 查询改为游标分批（cursor，3000/批）或做'加载更多'。
2. **扫描 Worker**：`dir.entries()` 的 `FileSystemDirectoryHandle` 无法发到 Worker（浏览器限制），保持主线程流式已是上限；可把"扫描→写库"再拆到 `setTimeout(0)` 分片，避免大事务长任务。
3. **缩略图进一步**：可做 128px 两档 + 按画廊尺寸自适应；当前 64px 够像素预览用。
4. **集群结果持久化**：`animsCacheRef` 目前会话内有效，重开页面首次进目录仍要重聚类（1-2ms，无感，可不做）。
5. **画廊分页**：48/页 + 触底加载已生效；如 11 万全览需要可加"跳页"或全量虚拟网格。
