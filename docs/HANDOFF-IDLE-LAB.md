## 3. 使用流程

1. 打开工具首页或直接进入 `/tools/idle-lab/`。
2. 不选择工程时可以使用内置演示地图熟悉操作。
3. 点击“选择工程”，选择 `D:\new-game` 工程根目录。
4. 页面读取 `Data/manifest.json`、角色属性定义、本地化、角色文件和地图 Excel。
5. 选择玩家角色，调整玩家属性和模拟假设。
6. 在地图中选择战斗关卡，调整通关条件和怪物倍率。
7. 点击“模拟当前关卡”检查单关结果。
8. 点击“运行全图体检”批量查找卡点。
9. 使用“流程推演”检查挂机、攒钱、升级和关卡推进节奏。
10. 分别保存方案 A、B，在“方案对比”中比较改动效果。
11. 用右上角导入、导出按钮保存完整验证方案。

验证方案不会写回游戏工程。它只保存验证台中的玩家、模型、关卡覆盖和地图快照。

## 4. 工程读取规则

### 4.1 读取文件

选择工程后读取：

- `Data/manifest.json`
- `Data/attribute.json`
- `Data/localization.json`
- `manifest.actors` 中登记的全部 `.actor`
- `manifest.others` 中名为 `地图格.<GUID>.xlsx` 的地图 Excel

浏览器支持 File System Access API 时使用目录句柄，并与现有角色、地图工具共享：

```text
IndexedDB: loot-smith-settings
key: last-project-handle
```

浏览器不支持目录句柄时，回退到 `webkitdirectory` 文件夹导入。兼容模式可以读取工程，但不会保存目录授权。

### 4.2 角色属性组

不能扫描整棵 `Data/attribute.json` 后按语义键取最后一项。`attack`、`defense` 等键会在角色、装备或其他属性组重复。

当前实现严格使用：

```text
attribute.settings.actor -> 对应角色属性根组 -> 只递归该组 children
```

真实工程当前关键角色属性 ID：

```js
name       = 'da4d32a4f1097059'
level      = 'fb9d675011f6c08f'
health     = 'a5fd5e9f229abb2d'
maxHealth  = 'a8451228fe0c120a'
attack     = '96efe7ef1b6999bc'
defense    = '752c94a8aa99161b'
critical   = '2b66c53fcb9e7680'
hit        = '8b294b83e30f41ac'
dodge      = 'd4f44a28ced26547'
attackTime = '843a8b363059e086'
healthRegen = '9a7528d2de781a0d'
rewardExp  = '47f57252180f77c7'
loopList   = '4cb407bd71929620'
```

代码会从角色属性组动态重建这些映射，常量只作为回退。

### 4.3 继承解析

角色按 `.actor` 的 `inherit` GUID 递归解析：

- 子角色本地属性优先；
- 本地未声明时读取父角色已解析值；
- 检测循环继承，遇到循环时停止；
- `maxHealth` 和 `health` 都映射到模拟中的 `hp`；
- `attack`、`defense` 等语义键必须映射到解析后的 `atk`、`def` 字段，不能直接按原键名读取父对象。

等级和名称有项目特例：

- 本地等级优先；
- 本地无等级时，优先解析文件名中的 `Lv5`、`Lv13`；
- 文件名也无等级时才继承父模板等级；
- 本地名称存在时使用名称或本地化文本；
- 本地无名称时显示具体资源文件名，不继承通用模板名“怪物”。

这样可避免所有怪物都显示同名，也避免模板 `level=1` 覆盖 `怪物005 - Lv5`。

### 4.4 金币期望值

金币物品 GUID：

```js
GOLD_ITEM_ID = '4280405b44a821f8'
```

同时读取：

- `loopList` 字符串属性；
- 角色事件中的掉落物品插件指令；
- 启用指令 `249c9c9d4de177c9`；
- 跳过以 `!` 开头的禁用指令。

金币期望：

```text
期望金币 = (min + max) / 2 × dropRate
```

同一角色多条金币掉落相加。当前模型不模拟装备出售价格或非金币物品的经济价值。

## 5. 地图数据规则

支持地图编辑器现有 10×10 JSON Schema，以及五工作表 Excel：

- 名称
- 等级
- 图标
- 通行
- 刷怪

每格核心结构：

```json
{
  "name": "芦苇平原",
  "icon": 1,
  "levelRange": { "min": 5, "max": 30 },
  "Passability": { "right": true, "down": false },
  "monsters": [
    { "id": "d4bf5e107664f5c1", "lvMin": 5, "lvMax": 30, "weight": 1 }
  ]
}
```

Excel 通行串继续保持：

```text
第一位 -> right
第二位 -> down
```

地图始终显示所有命名地点，但全图体检和流程推演只遍历 `monsters.length > 0` 的战斗关卡。城镇等非战斗地点不会被当成挂机流程起点。

真实地图验证结果：

- 50 个命名地点；
- 10 个带怪物池的战斗关卡；
- 自动选择的第一个战斗关卡为“芦苇平原”；
- 芦苇平原当前有 3 种怪物，对应 18 个怪物覆盖输入。

## 6. 模拟模型

### 6.1 定位

当前是可校准的离线近似，不是完整复刻 Yami 的事件机、动画帧、寻路、触发器、技能连段和状态系统。

目标是快速筛查：

- 数量级是否合理；
- 哪关会卡；
- 哪关死亡率异常；
- 通关时间是否偏离设计目标；
- 每小时经验和金币是否断层；
- 改一项参数后整体流程发生什么变化。

最终数值仍应通过游戏内实测校准。

### 6.2 默认伤害

数值模型自 v0.9.0 起对齐游戏实际（`docs/GAME-PLAY-LOGIC-CHAIN.md` §8 推理）：

```text
玩家伤害 = max(最低伤害, 玩家攻击 × 技能倍率 / 100 - 怪物防御 - 怪物基础防御)
怪物伤害 = max(最低伤害, 怪物攻击 - 玩家防御)
```

命中为阈值式（游戏实际，无 5% 下限）：

```text
命中率 = clamp((基础命中 + 攻击方命中 - 防守方闪避) / 命中骰子, 0, 1)
```

默认 `基础命中 80`（游戏「基础命中率」派生基准）、`命中骰子 80`。暴击时乘以可调暴击倍率，默认 `2`。

### 6.3 怪物等级成长

地图怪物条目可以给出 `lvMin/lvMax`。每次战斗按固定随机种子在区间内抽等级。成长为**线性**（对齐游戏通用怪物模板，游戏模板每级全部 +1）：

```text
生命/攻击/命中/闪避/经验 = 基础值 + 每级成长 × 等级差
防御不随等级成长（游戏模板无防御成长）
金币不随等级成长
```

默认 `每级成长 1`（与游戏模板一致）。

攻击间隔对齐游戏 `SPDTime` 公式：

```text
怪物间隔 = (attackTime × attackSpeed + 攻击速度基准 × 10) / 1000 秒
```

默认 `攻击速度基准 80`（游戏派生属性基准）。

### 6.4 单关 Monte Carlo

每次样本：

1. 先加入进场赶路时间；
2. 按怪物权重随机选择怪物，生成同场怪物数（默认 1）份同款；
3. 在等级区间内抽取等级；
4. 执行围攻战斗（玩家依次击杀当前目标，所有怪物按各自间隔攻击玩家）；
5. 胜利后累计击杀（每只 +1）、经验、金币并加入刷怪等待；
6. **死亡即本轮结束**（游戏实际无复活，队伍全灭即游戏结束）；
7. 达到通关击杀数时记录通关时间。

随机种子由地图来源、坐标、玩家参数、模型参数和关卡参数组成，同一方案结果可复现。

默认重复样本为 `200`，全图体检为避免阻塞会把每关样本上限临时限制到 `100`。

### 6.5 验证结论

当前结论阈值：

- 无有效怪物：错误；
- 通关率低于 50%：无法稳定通关；
- 无死亡样本低于 50%：死亡风险过高；
- 通关时间超过目标 150%：严重偏慢；
- 通关时间超过目标 120%：偏慢；
- 通关时间低于目标 55%：关卡过易；
- 其余：节奏健康。

这些阈值目前写在 `assessResult()`，后续如果策划需要，也可以改成页面参数，但当前没有必要再增加设置项。

## 13. 已知边界

1. 当前只模拟物理基础伤害，不解析每个 Yami 技能事件中的复杂技能公式。
2. 不模拟移动寻路、动画前后摇、攻击范围、碰撞、仇恨目标切换（围攻按顺序击杀当前目标）和刷怪位置。
3. 不模拟属性克制、护盾、眩晕、中毒、减速、魔法、召唤和多角色队伍；**经验按单人计**（游戏实际为全队在场合员各得全额）。
4. 金币以掉落期望值计算，不对每一件掉落执行独立随机，也不计算非金币物品价值（游戏实际每怪必掉 3 件装备）。
5. 流程推演只有一种攻击升级，不代表最终正式养成系统（游戏实际升级 = 等级 +1 + PT 手动加点，职业自动成长指令在游戏内被禁用）。
6. 地图路线按通行关系做广度优先排序；存在分叉时不模拟玩家主动选择收益最优路线（游戏实际为首次到达 BFS 渐进解锁、中间图走两遍、终点图无限往返）。
7. 验证参数只导出为方案 JSON，不写回角色、地图 Excel 或游戏变量。
8. 游戏当前**没有真挂机机制**（无自动战斗/离线收益/自动刷怪循环），验证台模拟的是目标态，数值模型已对齐当前游戏实测行为，形态假设（自动连续战斗）需在游戏挂机化后校准。
9. `app.js` 当前仍是单文件。用户明确要完整工具，本轮没有引入框架或抽象层；在出现真实重复维护成本前不要为了“结构好看”拆模块。

## 14. 下一步建议

优先级从高到低：

1. **做游戏内校准日志**：记录真实每场战斗耗时、承伤、击杀、金币和经验，与验证台预测对比，得到校准倍率。
2. **明确正式挂机循环**：确认关卡通关条件、死亡惩罚、自动推进、回退刷图和离线收益规则，再扩流程模型。
3. **加入装备/技能构筑快照**：从游戏存档或专用构筑 JSON 导入玩家最终属性，避免手工输入。
4. **经济价值表**：给材料、物品和装备出售/分解价值建立统一价值换算，扩展金币之外的收益指标。
5. **分叉路线策略**：让流程推演支持“最高经验、最高金币、最低风险”三种自动选图策略。
6. **校准后再写回**：只有验证模型与游戏实测误差稳定后，才考虑把关卡倍率导出给地图编辑器或正式数据表。

不要优先做：

- 把完整 Yami 事件机复制到网页；
- 直接修改 `D:\new-game`；
- 未校准前增加更多小数位或更复杂报表；
- 为当前单页工具引入 React/Vue 或新依赖。

## 15. 接手注意事项

- 修改前先运行 `self-check.js`，修改后再次运行。
- 角色属性只能从角色属性组解析。
- 不要让模板等级覆盖资源文件名中的明确等级。
- 非战斗地点可以显示，但不能进入战斗流程推演。
- 关卡怪物覆盖必须按地图坐标隔离。
- 固定随机种子是 A/B 可比较的基础，不要改回 `Math.random()`。
- 全图体检必须限制样本量，避免一次操作阻塞页面太久。
- 保持验证台只读工程；导出方案不能悄悄写回游戏数据。
- 当前仓库有用户已有的文档迁移改动，禁止擅自恢复旧根目录文档或删除 `docs/`。
- 未经用户明确要求，不要提交、推送或部署。
