## 0. 架构一句话

单进程 HTTP+SSE 宿主（默认 `127.0.0.1:5968`，`ai-host.js:17`）持有会话内存 Map（`ai-host.js:34`）与每工程一个内嵌 MCP 子进程（stdio JSON-RPC，`ai-host.js:797-867`）。
一轮对话 = `continueSession` 里的 `while` 步循环（`ai-host.js:1524-1684`）；写盘/编辑器动作类工具在循环中**暂停**并落一张待确认卡（`ai-host.js:1908-1911`），用户在面板点确认后由 `/approve` 从**同一条 SSE 通道**续跑（`ai-host.js:2402-2414`）。
工具能力 = 37 个 MCP 工具（`server.js:601-1060`），宿主对外只暴露其 `name/description/inputSchema`（`ai-host.js:869-871`）。

## 3. 免确认清单 & 删除类为何不给批量授权

**实际免确认的路径（`ai-host.js:1895` 单一判据推得）**
1. 只读工具（不在 FILE_MUTATIONS / OTHER_MUTATIONS 里，也不进确认分支）；
2. 写盘类的 `dryRun:true` 纯预览——只认**显式** `dryRun === true`，不传即视为会写（`ai-host.js:1876`、`ai-host.js:1895`）；
3. 已被授权的 `写盘类 + 该 path`（`ai-host.js:1894`）；
4. `approvalMode==='auto'` 时的编辑器动作类（同上 1895）；
5. `ui_steps`（在界面上"演"操作）**不在任何审批集合里** → confirm 模式下也不弹确认卡；对它只有"编辑器有未失焦输入就拦"的预检（`ai-host.js:1880-1893`）与面板的"撤销这一步"入口（`ai-agent.js:1340`、`ai-agent.js:2217`）。

**删除类为什么不给批量授权（三处独立闸门）**
- 宿主：`DELETE_TOOLS = new Set(['delete_resource'])`，`isGranted` 对删除恒 false、`addGrant` 对删除直接返回 null；注释写明"不可轻易撤销的动作不接受批量授权" —— `ai-host.js:1379`、`ai-host.js:1386-1392`、`ai-host.js:1394-1402`、`ai-host.js:1374-1379`；
- MCP：删除属 `HIGH_RISK_TOOLS`，正式执行必须带回 dryRun 预览发的一次性 `confirmationToken`（TTL 5 分钟、按 tool+path+oldSha 绑定、用后即弃）；只传 `force` 删不掉 —— `server.js:69`、`server.js:84-102`、`server.js:1476-1492`；
- 面板：`risk==='high'` 直接禁用并隐藏批量授权勾选 —— `ai-agent.js:1117-1119`。
- 另有工程保护：被引用（GUID 命中其它资源）时拒绝删除，除非 `force:true` 且卡片文案升级为【高危强删】 —— `server.js:1424-1442`、`server.js:1462-1464`。

**未覆盖的缝隙（事实）**
- 上下文压缩的摘要模型调用传 `cancelToken = null` → 停不下来（`ai-host.js:443-446`）；
- `/approve` 续跑排队的剩余调用时 `processToolCalls(session, pending.remaining, config, '', events)` **没传 cancelToken** → 这批工具不受取消控制（`ai-host.js:2290`，形参默认 null 见 `ai-host.js:1819`）；

- 编译检查不可取消（`server.js:1915-1929`，tsc 120s 硬超时）；
- `attachChangelog`、`saveSession`、`healSessionMessages` 等收尾步骤不看令牌（`ai-host.js:1341-1372` 等）。

## 14. 事实性缝隙候选（只陈述事实 + 锚点，不含对标结论）

1. **`ui_steps` 不受审批约束**：它既不在 `FILE_MUTATIONS` 也不在 `OTHER_MUTATIONS`，`needsApproval` 判据（`ai-host.js:1895`）对它为假；confirm 模式下会直接在编辑器里改属性/切页/点击，事后只有"撤销这一步"（`ai-host.js:1880-1893`、`ai-agent.js:1340`、`ai-agent.js:2217`）。
2. **`auto` 模式语义偏窄**：只豁免编辑器动作类，写盘类仍需每步确认（`ai-host.js:1895`）——即"自动"不含"自动写文件"。
3. **授权粒度与生命周期**：键是 `工具::path`，无 path 的写盘工具拿不到授权（`ai-host.js:1381-1384`）；授权跨轮存活到整段会话结束/手动清空，而文案与接口都称"本次任务"（`ai-host.js:1897`、`ai-host.js:2190-2192`、`ai-host.js:2313`）。
4. **取消覆盖不全**：压缩摘要调用无令牌（`ai-host.js:446`）、`/approve` 续跑的剩余调用无令牌（`ai-host.js:2290`）、MCP 层收到 `notifications/cancelled` 直接忽略（`server.js:2032`）、工具请求发出后无法真正中止（`ai-host.js:1720-1727`）。
5. **MCP 崩溃不可自愈**：子进程死后宿主不重建，同工程 `/project` 也不重建，需重启宿主或换工程（`ai-host.js:817-821`、`ai-host.js:864-867`、`ai-host.js:1943`）。
6. **压缩粒度 = 每轮一次**：长多步工具循环（几十步、每步大输出）在本轮内不再压缩，只能靠一级修剪兜底（`ai-host.js:1544` vs `1558`、`ai-host.js:403-410`）。
7. **会话目录全局不分工程**：`sessions/` 只有一层，历史列表会混进别的工程会话；恢复旧会话时 system 提示与工具集按当前工程走（`ai-host.js:60`、`ai-host.js:180-210`、`ai-host.js:1231-1240`）。
8. **工程根是进程级单例**：两个不同工程的窗口共用一个宿主时，后者的 `/project` 会顶掉前者并清空其内存会话（`ai-host.js:36`、`ai-host.js:1943`）。
9. **无网络层韧性**：无重试/退避/限流处理；模型流 180s、非流 120s、MCP RPC 180s 硬超时（`ai-host.js:1041`、`ai-host.js:971`、`ai-host.js:849`）。
10. **死代码/未接线项**：非流式 `requestModel`（`ai-host.js:964`）无调用；常量 `MAX_STEPS`（`ai-host.js:62`）无读取；`busySend`（queue/interrupt）宿主只存取不分支，行为全在面板（`ai-host.js:617,783`、`ai-agent.js:2338`）。
11. **审批卡信息不对称**：非写盘类动作（编辑器点击/试玩输入等）没有预览，卡片 `preview:null`、risk 默认 medium（`ai-host.js:1256`、`ai-host.js:1900`）。
12. **每轮都全量重发 36 个工具 schema**（无按任务裁剪），固定开销被算进上下文与压缩阈值判断（`ai-host.js:1541`、`context-meter.js:94-107`、`context-meter.js:212-220`）。
