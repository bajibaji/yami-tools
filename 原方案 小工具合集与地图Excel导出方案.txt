Yami Tools 小工具合集与地图 Excel → JSON 导出方案
===================================================

本文只提供实施方案，不修改游戏工程数据。

仓库：D:\Documents\GitHub\yami-tools
游戏工程：D:\new-game
GitHub Pages：https://bajibaji.github.io/yami-tools/


一、目标
--------

将现有网站改造成“小工具合集”。

1. 根目录主页不再直接进入当前角色编辑器。
2. 当前工具改名为“角色编辑”。
3. 新增“地图 Excel 导出”工具。
4. 新工具读取：

   D:\new-game\Assets\UI\地图\地图格.34eee41059f43f30.xlsx

5. 读取规则以以下 Yami Excel 指令为准：

   D:\new-game\Assets\插件\自定义指令\Excel操作.指令.54a6570d8aa52362.ts

6. 新工具在浏览器本地将 Excel 转成 JSON，供 Yami 运行时加载。


二、重要结论
------------

现有 Excel 数据链路：

读取excel.3739667372fedf5f.event
  → 读取 地图格.34eee41059f43f30.xlsx
  → 工作表 1：名称
  → 工作表 2：等级区间
  → 工作表 3：图标
  → 工作表 4：通行状态
  → 工作表 5：刷怪列表
  → 写入五个全局对象变量

现有五个回调事件是 ExcelJS 的“工作表转二维数组”回调，不能原样读取 JSON。

因此推荐方案是：

1. 网站负责 Excel → JSON；
2. Yami 端新增一个“地图 JSON 读取”指令或等价加载器；
3. 加载器直接写入五个全局变量；
4. 原五个 Excel 回调事件暂时保留作为旧版兼容；
5. 原统一入口事件保持 GUID 不变，只替换内部实现。

六、Excel 插件的真实读取规则
----------------------------

原 Excel 操作插件在“转换为二维数组”时：

1. 使用 ExcelJS 读取指定工作表。
2. worksheet.eachRow({ includeEmpty: true })。
3. row.eachCell({ includeEmpty: true })。
4. 空单元格使用 null。
5. 将二维数组传给后续回调事件。

注意：原插件会把格式残留也算入 rowCount。

真实工作簿的五张表使用 ExcelJS 读取时，都会被格式撑到 200 行。
名称表还会被撑到 12 列。

但真实有内容的范围均为：10 行 × 10 列。

现有地图 UI 也固定按 10 行 × 10 列消费五个数组。

因此，新导出器必须标准化输出：

rows = 10
columns = 10

规则：

1. 只允许裁剪第 11 行以后、第 11 列以后全部为空的区域。
2. 裁剪时显示警告，例如：

   “检测到 Excel 格式残留：名称表报告为 200×12，实际内容为 10×10，已安全标准化。”

3. 第 11 行以后或第 11 列以后存在真实值时，阻止导出。
4. 10×10 内缺失单元格必须补 null。
5. 不允许 filter(Boolean)、trim 空行、压缩行列，否则地图坐标会错位。


七、字段校验规则
----------------

名称表：

string 或 null

等级区间表：

null、数字 0、或字符串，例如：

5～30
60～70

输入允许：

5-30
5~30
5～30

导出统一为全角波浪号：

5～30

图标表：

整数。

-1 表示不可用/空地。
0 和正整数是图标类型，不能错误视为“空”。

通行状态表：

null 或：

0,0
0,1
1,0
1,1

刷怪列表表：

null、-、或逗号分隔的 Actor GUID：

d4bf5e107664f5c1,421b5f9cee70b119

校验：

1. GUID 必须为 16 位十六进制。
2. 选择游戏工程时，校验 GUID 对应 .actor 文件是否存在。
3. “-” 保留原样，不转换为 null。
4. Excel 公式、日期、错误值、富文本、超链接对象在 MVP 中禁止导出，并定位单元格报错。

已确认当前 Excel 中的刷怪 GUID 均有效。


八、推荐 JSON 格式
------------------

真实导出必须为 10×10。下面是缩小后的 2×3 结构示例，仅用于展示：

{
  "format": "yami-world-map-grid",
  "version": 1,
  "source": {
    "fileName": "地图格.34eee41059f43f30.xlsx",
    "sheets": ["名称", "等级区间", "图标", "通行状态", "刷怪列表"]
  },
  "grid": {
    "rows": 2,
    "columns": 3
  },
  "globalVariables": {
    "b266af08c47fc3b4": {
      "name": "地图名称",
      "value": [
        [null, "边境哨所", null],
        [null, "芦苇平原", "狂风山道"]
      ]
    },
    "c13d5157ada76039": {
      "name": "地图等级分布",
      "value": [
        [null, 0, null],
        [null, "5～30", "60～70"]
      ]
    },
    "6fb261049614e47c": {
      "name": "地图icon分部",
      "value": [
        [-1, 0, -1],
        [-1, 1, 5]
      ]
    },
    "baf6c5f5164a98cf": {
      "name": "地图icon连线",
      "value": [
        [null, "0,1", null],
        [null, "1,1", "0,1"]
      ]
    },
    "9dadd844e12cb6cb": {
      "name": "地图刷怪列表",
      "value": [
        [null, "-", null],
        [null, "d4bf5e107664f5c1,421b5f9cee70b119", "-"]
      ]
    }
  }
}

推荐使用全局变量 ID 作为 globalVariables 的键。

原因：Yami 加载器可以直接执行：

for (const [variableId, entry] of Object.entries(data.globalVariables)) {
  Variable.set(variableId, entry.value)
}

加载器必须先完整验证全部五组数据，再一次性写入五个变量。
验证失败时不能只更新其中几项，避免地图处于半更新状态。


九、Yami 运行时的 JSON 加载方案
--------------------------------

建议新增自定义指令：

地图JSON读取.指令.ts

JSON 建议放在：

Assets/UI/地图/地图格数据.<新GUID>.json

并登记到 Data/manifest.json 的 others 资源中。

加载器必须兼容：

1. Electron/编辑器环境：fs.readFileSync。
2. 发布浏览器环境：fetch(Loader.route(...))。

统一入口事件必须继续保持原 GUID：

读取excel.3739667372fedf5f.event

原因：以下两个事件已经调用它：

@5 新的游戏.40b2ca62601a61b7.event
@6加载存档.e4b32024ea7435a1.event

迁移做法：

1. 保留读取excel事件文件和 GUID。
2. 移除其 Excel read/to-array 链。
3. 改为调用地图JSON读取指令。
4. 地图JSON读取直接设置五个全局变量。
5. 原五个 Excel 回调事件先保留，作为开发期/回滚兼容。

这样新游戏和读档的调用方不用改。
