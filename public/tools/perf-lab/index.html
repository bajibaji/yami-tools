使用说明

核心思路：性能分析台不模拟游戏，只分析你在真实 Electron 游戏里录到的报告。你先采集，再导回来定位问题。

先选路线

  • 只想知道“主线程是不是太忙” → 路线 A（DevTools Performance）
  • 排查渲染 / Draw Call / 纹理内存 → 路线 B（Spector.js）
  • 想定位“哪段代码把帧顶超 16.7ms” → 路线 C（真机探针，最推荐）

A 最快看 CPU / 长帧（DevTools Performance）

  1. 在游戏试玩窗口 / 打包游戏里按 F12 打开 DevTools；
  2. 切到 Performance 面板，点录制（圆点）；
  3. 正常游玩并复现卡顿，录 15～60 秒；
  4. 停止录制，点保存 / 导出为 trace JSON；
  5. 回到本工具，把 JSON 拖进「DevTools Performance」区域。
不要同时运行真机探针：探针会进入 CPU Profile，污染热点结果。路线 A 与路线 C 必须在同一场景分别复现两次。

能看：主线程长任务、CPU 热点函数、GC、帧间隔 P95。适合先确认“是不是主线程太忙”。

B 看 WebGL（Spector.js）

  1. 获取 Spector.js 上游仓库的 extensions/ 目录；
  2. 让游戏 / 编辑器加载该扩展（编辑器安装目录扩展目录，或打包游戏主进程 loadExtension）；
  3. 在游戏里用 Spector 捕获目标画面，保存 capture JSON；
  4. 把 JSON 拖进「Spector.js」区域。

能看：Draw Call、GL 命令、冗余状态、纹理 / 缓冲内存、WebGL 上下文。适合排查“渲染 / GPU 侧瓶颈”。

C 推荐：定位 16.7ms 超帧元凶（Yami 真机探针）

  1. 在左侧「真机探针」点「复制探针脚本」；
  2. 关闭并重新打开游戏窗口，卸载之前运行过的旧探针；
  3. 打开 Electron 游戏窗口，按 F12 → Console，先输入 typeof Game——必须是 "object"；
  4. 粘贴探针脚本并回车，正常游玩卡顿片段；
  5. 游玩结束，执行下面这段完整代码，直接下载 JSON；
  6. 把下载的 .json 文件拖回「Yami 真机探针」区域。
完整命令行（在游戏 DevTools Console 里依次执行）
// 第一步：粘贴探针脚本（工具页左侧「复制探针脚本」获取）
// 第二步：正常游玩卡顿片段
// 第三步：导出结果（推荐 download，直接下载 JSON 文件）
window.__YAMI_PERF_PROBE__.check() // 可选：确认 game/updaters/samples 是否正常
window.__YAMI_PERF_PROBE__.download()

// 如果想复制到剪贴板（再手动保存成 .json），改用：
// window.__YAMI_PERF_PROBE__.copy()

能看：每帧计算耗时（Game.update + render）、超 16.7ms 的帧里到底是哪个更新器 / 渲染器 / 事件最耗时。这是回答“哪段代码把帧顶超”的主力路线。

注意：如果 typeof Game 不是 "object"，说明探针跑在了错误页面，数据会是空的（updaters: []、scene: null）。必须在游戏自己的 DevTools Console 里跑。

导入后怎么看

  • 总览：先看帧预算 / 长任务 / GC / 超预算帧。有红色诊断就先处理。
  • CPU 与长帧：CPU 热点按总耗时排序，定位到 Dist/Script/*.js:行号；长任务看卡顿瞬间。
  • WebGL：Draw Call 高、冗余命令多、纹理内存大时去查渲染 / 粒子 / 图层。
  • 超帧定位：先看归因覆盖率；覆盖足够时才看高置信元凶。覆盖不足会明确要求重采，不会硬猜。

基线怎么用

导入报告后点「保存基线」记录当前摘要。以后改完代码再录一次并导入，总览卡片会出现绿色 / 红色差值（+0.42 表示变差），帮你判断这次改动有没有让性能退化。

常见坑

  • DevTools 录制必须导出 trace JSON，只截图 Performance Monitor 导不进来；
  • 探针脚本必须在游戏运行时的控制台里粘贴（不能在其他页面粘贴）；
  • 如果导出的 JSON 是空（samples: 0、hooked.game: false），先用 window.__YAMI_PERF_PROBE__.check() 看看，再去游戏 Console 里跑；
  • 探针只统计主线程 JS 计算，GPU / 渲染实际耗时需要配合 Spector 看；
  • 不同机器的 GPU / CPU 不同，对比时尽量同一台机器、同一场景、同一分辨率。
