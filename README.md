
# ya的YAMI妙妙小工具


纯静态 Web 工具合集，所有工程文件均在浏览器本地读取和处理。

## 工具

- **角色编辑器**：编辑角色掉落、掉落事件和人物属性，保存前自动备份。
- **地图编辑器**：导入 Excel / JSON，编辑 10×10 地图格、通行关系、等级和刷怪池。
- **挂机验证台**：读取角色、地图和掉落数据，按游戏实际数值模型模拟单关战斗、全图节奏、长期成长和 A/B 数值方案。
- **快速本地化**：只扫描游戏里被引用的资产（复刻引擎打包算法），找出未本地化的硬编码文本、缺翻译条目、孤儿引用与疑似占位翻译；支持界面内直接编辑原文/译文（含缺翻译/疑似占位的中文原文）、一键本地化、孤儿修复，也支持导出多语言 Excel 走翻译流程导入回工程（**含与 Yami 编辑器本地化界面同算法的 `open-yami` 引擎格式表**；全程自动备份，可还原）。
- **存档台**：读取游戏工程 `Save/` 目录，格式化查看存档 JSON（v1/v2 稀疏格式）与 `.meta` 截图；可把存档里的 GUID 和键名注解成游戏内的中文名称与图片（角色/队伍/技能/状态/装备/物品/事件/场景/属性/变量/本地化条目）；支持编辑写回（保存前自动备份到 `Lootsmith Backups`），游戏内存档后自动刷新。

## 存档台

工程位置与其他工具联动（同一 IndexedDB 工程记忆，打开自动加载上次选择的工程）。支持：

- **存档文件列表**：`saveNN.save`（进度存档）/ `saveNN.meta`（时间戳+截图）/ `global.save`（全局设置）/ `saveNN.json`（插件旁路数据）/ `.bak` `.tmp`。
- **格式化 JSON 树**：可折叠、语法高亮、全部展开；文件信息栏显示版本（v2=稀疏格式）、游玩时间、角色数、槽位。
- **中文/GUID 映射开关**：把存档词条注解成游戏内内容——`fileId`→角色中文名、`teamId`→队伍名、技能/状态/装备/物品/事件/场景 ID→中文名、属性键→中文属性名、变量 ID→中文变量名、`plugins` GUID→插件名、`portrait`/`icon`→按 `clip` 裁剪的头像/图标图片、`timestamp`→保存时间、`playTime`→时长、`screenshot`→截图预览。
- **编辑写回**：编辑模式（格式化 JSON）→ 语法校验 → 确认 → 自动备份到 `Lootsmith Backups/<时间戳>/` → 写回（紧凑 JSON，与引擎格式一致；不碰引擎的 `.bak`）。游戏运行时写档可能覆盖修改，保存前会提醒。
- **自动刷新**：5 秒轮询 Save 目录，游戏内存档后自动重新读取（编辑模式暂停）；浏览器模式（IndexedDB 存档）不可见，仅桌面工程。

不支持 File System Access API 的浏览器自动进入只读导入模式（可查看与下载修改副本）。

## 挂机验证台

验证台默认提供一套演示地图，也可选择 Yami 工程后读取真实角色与地图 Excel。支持：

- 调整玩家生命、攻击、防御、攻速、技能倍率、命中、闪避、暴击和恢复。
- 调整模拟假设：怪物每级成长、攻击速度基准、命中骰子范围、同场怪物数、暴击倍率、最低伤害等。
- 单独覆盖每关通关击杀数、刷怪等待、赶路时间、金币倍率与目标时间。
- 单独覆盖每个关卡中每种怪物的权重，以及生命、攻击、防御、经验、金币倍率。
- 固定随机种子的重复战斗模拟；每关结果面板显示验证结论、通关时间对比、生存率与每小时收益，以及每只怪物缩放后的实际属性。
- 10×10 热力图与地图编辑器同款显示：轴标签、地标图片、图标/怪物数/等级角标、通行边、缩放滑块与图标图例，热力值叠加在格子上。
- 全图体检按严重程度列出卡点、奖励异常和空关卡。
- 按地图通行关系推演挂机、攒资源、购买升级和解锁关卡的时间线。
- 保存 A/B 快照，比较通关时间、生存率和每小时收益。
- 导入、导出完整验证方案；验证参数不会写回游戏工程。

验证模型对齐游戏实际数值（2026-08-12 从 `D:\new-game` 源码推理）：怪物每级线性成长（游戏模板每级 +1，作用于生命/攻击/命中/闪避/经验）、`attackTime × attackSpeed + 攻击速度基准 × 10`（毫秒）的攻击间隔、`(基础命中 + 命中 − 闪避) / 命中骰子` 的阈值命中（游戏骰子 80、无下限）、同场多怪围攻、死亡即本轮结束。它用于快速筛查节奏与数量级，最终结果仍应以游戏内实测校准。

## 使用

1. 用支持 File System Access API 的浏览器打开 `index.html`（Chrome / Edge / Yami 编辑器内置 Chromium），再选择需要的工具。
2. 点击“选择工程”，选择包含 `Assets`、`Data` 的游戏工程根目录。
3. 工具会递归扫描 `.actor`、`.item`、`.equip` 文件，并从 `Data/attribute.json` 读取属性名称映射。
4. 同时读取 `Data/localization.json`，将 `<ref:本地化ID>` 解析为中文名称；角色头像、物品图标和装备图标按资源 `portrait` / `icon` 与 `clip` 自动裁切预览。
5. 选中角色，在右侧选择物品或装备、填写数量，点击“插入掉落物”。角色列表、掉落列表和资源列表均有独立滚动区域。
6. 角色列表右上角提供排序下拉：文件名 / 名称 / 修改时间 × 升序 / 降序共 6 种，默认按文件名升序（数字按自然序，如“怪物2”排在“怪物13”前）；选择会被记住，下次打开保持。
7. 点击“保存当前角色”或“保存全部更改”后才会把数组 JSON 字符串写入角色的 `loopList` 属性。

## 快速本地化

选择游戏工程后自动扫描六类内容（**默认只扫描游戏里被引用的资产**——引用判定复刻引擎打包算法，闲置资产如「旧装备」「废弃人物」不会浪费你的时间，可勾选「含未引用资产」查看全部）。两个核心功能：① 找**已经本地化且会在游戏界面出现的中文**，快速编辑译文和原文；② 快速找**还未本地化但会在游戏界面出现的中文**——判定依据是引擎运行时事实：只有进入界面文本元素的内容才走 `<ref:>` 替换，内部文件不用本地化。

- **待本地化候选（界面）**：界面显示路径上尚未包 `<ref:ID>` 的硬编码中文（高置信）与英文（中置信，需人工确认）——.ui 界面文本、对话框、写入界面的值模板；被事件 setText 覆盖的节点（占位模板）自动排除。同文本自动合并为一个条目，每条候选有**唯一 ID**（与引擎同格式的 16 位 hex），原文下方可见。开发者注释、条件比较值、数据标识、裸标签与 ref 后缀（`]x2`/`X10`）等噪声一律不计入。
- **缺翻译条目**：被引用的 `localization.json` 条目中缺失某些语言译文。
- **孤儿引用**：`<ref:ID>` 指向不存在条目的引用，附建议文本，可一键按现有引用 ID 创建缺失条目。
- **疑似占位**：译文是占位脏词（shit/test/待翻译…）的条目；「与原文相同」不再判定（那是开发者有意保留原语言的状态）。
- **已本地化**：界面显示路径引用的条目——**中文原文与译文都可以直接在界面里编辑**（单语言模式，语言下拉切换），保存时自动备份写回。
- **富文本正常显示**：原文与译文里的标签会解析成实际内容——`<color:…>` 上色（含颜色索引）、`<global:ID>` 显示变量名、`<ref:ID>` 显示引用的中文、`<image:…>` 直接显示图片；候选/已本地化/缺翻译/疑似占位/数据属性各视图默认都这样显示，点 ✎ 编辑时切换为原始源代码（多行可拖拽 textarea，自动增高）。
- **数据属性**：物品/技能/装备/状态等数据文件的名称与描述——上半部分未本地化候选（同样可一键本地化），下半部分属性引用的已本地化条目（可编辑原文/译文）。

两种写入方式：① **界面直接操作**——候选行点「本地化」立即创建条目并替换文件原文（无需 Excel）；缺翻译/疑似占位/已本地化视图直接改文本后点「保存修改」；② **Excel 流程**——导出七 sheet（**首表 `open-yami` 引擎格式**：ID/Name/各语言/parentID/isDir，与 Yami 编辑器「保存到Excel」同算法，导入时整树替换 localization.json；其余为待本地化/数据属性/缺翻译/疑似占位/孤儿引用/说明工作流表）交给翻译人员填写后导入回工程。两种方式都会：先备份到 `Lootsmith Backups/<时间戳>/`（顶栏「备份与还原」面板可查看、一键还原、删除），写回格式与原文件一致（Yami 编辑器不产生大 diff），同一 Excel 重复导入安全。

语言列完全由 `Data/config.json` 的 `localization.languages` 驱动——未来扩展到 16 国只需在配置中追加语言并重新导出，工具无需改动。

## 工程自动同步

四个工具（角色编辑器、地图编辑器、挂机验证台、快速本地化）都会监听游戏工程文件变化：

- 优先使用 `FileSystemObserver`（Chrome 133+），文件变化即时触发；不支持的浏览器回退为每 5 秒检查一次文件修改时间，页面切到后台时暂停。
- 角色编辑器有未保存修改时不会自动刷新（避免丢失草稿），会提示“保存后将自动同步”，保存完成后自动刷新。
- 地图编辑器提供“重新扫描”按钮，可随时手动刷新工程资源。
- 快速本地化检测到变化时只弹提示、**不自动重扫**（避免打断编辑中的草稿），点“重新扫描”刷新；工具自身的写入（本地化/保存修改/导入/孤儿修复）走增量刷新，不重扫工程。
- 导入预览模式（浏览器不支持直接写回文件夹时）无法监听文件变化，不自动同步。

## 安全机制

- 首次选择工程后会把目录句柄保存在浏览器本地。下次打开工具，若浏览器权限仍有效会自动加载；否则点击“加载上次工程”重新授权即可。
- 直接写回工程前，先在工程根目录创建 `Lootsmith Backups/<时间戳>/`，以 `.actor.bak` 扩展名备份所有即将修改的角色文件并逐个回读校验；该扩展名不会被 Yami 当成角色资源扫描。备份失败或发现文件被外部修改时，原文件不会写入。
- 批量保存如果中途失败，会用本次备份自动回滚已经写入的角色；无法回滚时保留备份目录供手动恢复。
- 快速本地化的每次写回（本地化/保存修改/导入/孤儿修复）都会在 `Lootsmith Backups/<时间戳>/` 备份待写文件；顶栏「备份与还原」面板可浏览历史备份、立即备份、一键还原（还原前自动再快照当前状态，可反悔）或删除备份。
- 不支持 File System Access API 的浏览器进入导入预览模式，保存只下载修改副本，不覆盖工程文件。

## 写回格式

属性模式下新建或标准化的掉落列表字符串格式为：

```json
[{"type":"item","id":"物品GUID","min":1,"max":3,"dropRate":0.04},{"type":"equipment","id":"装备GUID","min":1,"max":1,"dropRate":1}]
```

工具优先更新角色根对象的 `loopList`；否则更新 `attributes` 中 ID 为 `4cb407bd71929620`（或属性键为 `loopList`）的字符串；如果不存在则创建该属性。

## 掉落参数与写入模式

- 物品：支持固定数量（`min=max`）或数量范围（`min` 到 `max`）。
- 装备：插件实际按单件装备处理，网页固定写入 `min=1`、`max=1`，不会伪造装备数量。
- 掉落几率：网页使用百分比，支持小数（如 `0.5%`），保存为 `dropRate: 0.005`；滑块与输入框步进 `0.01`，0~1% 区间可精细微调；`100%` 保存为 `dropRate: 1`。
- **物品价格与总价值**：掉落物品库每行名字右侧显示物品价格（货币单位 G，读自物品/装备的「价格」属性）；「掉落列表」标题右侧显示掉落物总价值 = Σ(物品价格 × 掉率 × 期望数量)，数量范围取 min/max 中值，禁用的掉落不计入。
- **继承事件**：角色事件模式下可勾选「继承事件」，保存时在掉落命令最上方插入 `callEvent(type: inherited)`，让该角色掉落继承父级事件上下文；取消勾选则移除。
- **属性字符串**：写入 `loopList`，保留便于其他逻辑读取的列表模式。
- **角色事件**：写入角色的“掉落物品”角色事件（当前工程事件类型 ID 为 `c2ba6c4f90edd668`），仅替换掉落物品插件指令，保留同一事件内的其他指令、启用状态和未知参数。角色没有本地掉落事件时按空列表显示，编辑保存时在角色本地**新建空掉落事件**；不读取、不修改父角色/通用模板的掉落事件。
- 角色事件模式下，每条掉落物右侧都有禁用开关；禁用后保存为 `!249c9c9d4de177c9`，启用后保存为 `249c9c9d4de177c9`，不会删除掉落配置。

如果浏览器不支持直接写入文件夹，工具会自动切换为只读导入模式，保存时下载修改后的 `.actor` 文件。

## 人物属性编辑模式

- 默认打开的是掉落编辑器。人物属性模式**必须手动点击**“人物属性编辑”按钮进入，且不会记住上次模式：刷新、重新扫描后仍回到掉落编辑。
- 进入后展示当前角色的 `attributes` 数组：本地属性可编辑，继承属性只读并显示来源，可“创建本地覆盖”（只写当前角色，绝不修改父角色文件）。
- 支持四种类型：`number`（允许 0、负数和小数）、`boolean`（写回真布尔值）、`string`（保留原始文本，`<ref:...>` 本地化引用不会被自动替换）、`enum`（下拉选择，写回的是枚举项 ID，不是 `value`）。
- 可从 `Data/attribute.json` 的角色属性定义中添加当前角色尚未拥有的属性；已继承但无本地值的属性会变成“创建本地覆盖”。
- 未知属性（定义中不存在）会原样显示和保留，不会被隐藏或删除；删除未知属性需要二次确认。未知枚举值也会保留，不会被静默替换成第一项。
- `loopList` 在人物属性编辑器中只读，由掉落编辑器统一管理，防止两份草稿互相覆盖。
- 所有修改先进草稿，只有点击“保存当前角色”或“保存全部更改”才写回，写回前仍然创建并校验备份；保存顺序固定为人物属性 → loopList → 角色事件，重建 `attributes` 数组后会重新定位 loopList 槽位，不会写错位置。
- 注意：修改人物属性可能影响战斗、AI 与旧存档兼容性，保存前请确认。
