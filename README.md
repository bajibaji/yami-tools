# YA的YAMI妙妙小工具

纯静态 Web 工具合集，所有游戏工程文件都在**浏览器本地**读取和处理，不上传任何数据。专为 Open Yami RPG Editor（Yami RPG Maker）工程设计。

工具列表：

| 工具 | 一句话说明 |
|---|---|
| **存档台** | 查看/编辑游戏存档（Save 目录），GUID 自动翻译成中文与图片 |
| **角色编辑器** | 可视化编排角色掉落表、掉落事件与人物属性 |
| **地图编辑器** | 10×10 地图格、通行关系、等级和刷怪池的 Excel/JSON 编辑 |
| **挂机验证台** | 按游戏真实数值模型模拟战斗/成长/收益，定位数值瓶颈 |
| **性能分析台** | 分析 Electron 真机游玩的 DevTools trace 与 Spector.js WebGL capture |
| **快速本地化** | 找未本地化文本、缺翻译、孤儿引用，导出/导入翻译 Excel |
| **脚本转换台** | 老版 Yami JS 插件与指令一键转换为现代规范 TypeScript (TS) 代码 |

## 快速开始（第一次用，3 步）

**① 打开工具**：两种方式任选

- 线上版：GitHub Pages <https://bajibaji.github.io/yami-tools/>（推荐，无需安装）
- 本地版：仓库根目录执行 `python -m http.server 4173`，浏览器打开 <http://127.0.0.1:4173/>

**② 用 Chrome / Edge 打开**（或 Yami 编辑器内置 Chromium）。这些浏览器支持「File System Access API」，可以直接读写工程目录；其他浏览器会自动降级为只读导入模式（能看、能下载修改副本，不能写回）。

**③ 选择游戏工程**：点「选择工程」，选中游戏工程的**根目录**（包含 `Assets`、`Data`、`Save` 的那个文件夹，例如 `D:\new-game`）。

> **工程位置是五个工具共用的**：任何工具选择过的工程都会被记住（浏览器本地保存），其他工具打开时自动加载上次工程，点「加载上次工程」重新授权即可，不需要每个工具都选一遍。

## 存档台（v0.1.1）

### 这个工具解决什么问题（用在哪）

游戏存档 `Save/saveNN.save` 是给引擎读的 JSON，直接打开是**一大串没有意义的 GUID 和英文键**：

```json
{"playTime":3045,"actors":[{"fileId":"1ab20a44c47972b7","teamId":"2a6ee1684ef7dfa0","attributes":{"level-EX":5}}]}
```

存档台把这一串翻译成人话：

```json
{"playTime": 3045, "actors": [{"fileId": "@1 通用英雄角色", "teamId": "NPC 队伍", "attributes": {"level-EX": "等级加成(5)"}}]}
```

典型使用场景：

- **调试存档**：玩家报错/进度丢失时，打开存档看角色、背包、变量到底存了什么。
- **改数值**：给角色改金币/等级/属性、改变量、改背包——保存前自动备份，改坏了能还原。
- **验证存档格式**：检查 `version` 是否为 2（v2 稀疏格式）、属性是否只存了变化值、meta 截图是否正常。
- **排查坏档**：主档损坏时引擎会自动读 `.bak`；存档台可以单独打开 `.bak` 对比内容。
- **对照测试**：游戏里改了什么 → 存档里对应哪个字段（中文映射一开就看懂）。

### 怎么用（操作步骤）

1. 主页点「**存档台**」→ 选工程（或自动加载上次工程）。
2. 左侧是 **Save 目录文件列表**，按用途分组：

   | 分组 | 文件 | 说明 |
   |---|---|---|
   | 进度存档 | `save00.save`、`global.save` | 游戏进度 / 全局设置+共享变量 |
   | 元数据 | `save00.meta` | 保存时间 + 截图 |
   | 旁路数据 | `save00.json` | 插件（Excel操作改2）额外写的自定义数据，与引擎存档无关 |
   | 备份文件 | `*.bak` | 引擎自动保留的上一份存档 |
   | 其他文件 | zip / vdf 等 | 与存档无关的杂物 |

3. 点文件名 → 右侧显示 **JSON 树**（默认展开第一层，深层点击 `▸` 才展开，大存档也不卡）：
   - 文件信息栏：版本（v2=稀疏格式）、游玩时间、角色数、槽位、修改时间。
   - `.meta` 文件顶部直接显示**截图预览**和保存时间；JSON 树里的 `data:image` 值也内嵌缩略图。
4. **「显示中文/GUID 映射」开关**（默认开）：把存档里的键和值注解成游戏内内容，注解是蓝色小标签，不改变 JSON 本身的颜色。覆盖范围：

   | 存档里的东西 | 会显示成 |
   |---|---|
   | `fileId` / 技能 / 状态 / 装备 / 物品 / 事件 / 场景 ID | 对应资产的中文名（角色「史莱姆」、技能「900 - 攻击」…） |
   | `teamId` | 队伍名（NPC / 玩家 / 魔物） |
   | 属性键（`STR`、`level-EX`…） | 属性中文名（力量、等级加成…） |
   | 变量 ID（含 `global.save` 的共享变量） | 变量中文名（夜晚、地下城目标…） |
   | `plugins` 里的 GUID | 插件名 |
   | `portrait` / `icon` | 按 `clip` 裁剪的头像/图标**图片** |
   | `timestamp` / `playTime` | 保存时间 / 游玩时长 |
   | `screenshot` | 截图缩略图 |

5. **「源码」按钮**切换成纯文本视图；**搜索框**在源码里定位内容（即时计数 `n/m`、`↑↓` 跳转、回车下一个）——5MB 大档也能秒搜。
6. **编辑存档**：点「编辑」→ 在文本框中改 JSON（格式化显示）→ 点「保存修改」：
   - 先做语法校验（写错会提示，不会保存）；
   - 弹窗确认（**建议先关闭游戏**，否则游戏下次存档会覆盖你的修改）；
   - 自动把原文件备份到工程根目录 `Lootsmith Backups/<时间戳>/`；
   - 以紧凑 JSON 写回（与引擎格式一致，不动引擎自己的 `.bak`）。

### 举个实际例子：给玩家改钱

1. 存档台 → 选择工程 → 点 `save00.save`。
2. 展开 `actors`，找到玩家角色（`fileId` 注解会显示中文名）。
3. 展开该角色 → `inventory` → `money`，看到当前金币数。
4. 点「编辑」，把 `money` 改成目标值，点「保存修改」→ 确认 → 自动备份完成。
5. 进游戏读档即可（注意：如果游戏还开着，先关掉再改，或改完不要触发游戏内保存）。

### 注意事项与限制

- **游戏运行时编辑会被覆盖**：游戏进程可能在你修改后保存存档，覆盖工具写回的内容。修改前请关闭游戏，或修改后不要再在游戏里存档。
- **只读导入模式**：浏览器不支持直接写文件夹时（Firefox/Safari 等），只能查看和下载修改副本。
- **浏览器模式存档不可见**：网页版游戏（IndexedDB 存档）不在工程 Save 目录里，本工具只支持桌面版工程的存档。
- **映射需要工程数据**：GUID 翻译依赖工程的 `Data/manifest.json`、`attribute.json`、`variables.json`、`teams.json` 等文件；资产文件被删或 manifest 未更新时，个别 GUID 会没有注解（属正常）。

## 角色编辑器

可视化编排角色掉落表（两种写入方式）与人物属性，保存前自动备份。

- **掉落编辑**：扫描角色/物品/装备，拖拽或点选添加掉落物，支持固定数量/数量范围/掉落几率（小数百分比）、物品价格与掉落总价值、继承事件、事件模式逐条禁用；保存写入 `loopList` 属性或「掉落物品」角色事件（保留未知指令）。
- **人物属性编辑**：本地属性可编辑、继承属性只读可覆盖；支持 number/boolean/string/enum 四种类型；未知属性原样保留。
- 使用步骤：选工程 → 选角色 → 配置掉落 → 保存（自动备份 + 失败回滚）。

## 地图编辑器

支持导入 Excel / JSON，可视化编辑 10×10 地图格、通行关系、等级区间、刷怪池，一键导出 Yami 标准地图 JSON（`地图JSON读取` 指令配套格式）。

## 挂机验证台

读取真实工程的角色/地图/掉落数据，按游戏实际数值模型模拟单关战斗、全图节奏、长期成长与 A/B 数值方案：可调玩家属性与模拟假设、逐关覆盖怪物权重与倍率、固定随机种子重复模拟、10×10 热力图、全图体检、时间线推演、A/B 快照对比。**验证参数不会写回游戏工程**。

数值模型已对齐游戏源码（怪物每级 +1 线性成长、攻击间隔公式、阈值命中骰子 80 等）；用于快速筛查节奏与数量级，最终以游戏内实测为准。

## 快速本地化

只扫描**游戏里被引用的资产**（复刻引擎打包算法），找未本地化的硬编码文本、缺翻译条目、孤儿引用与疑似占位翻译。两种工作流：

- **界面直改**：候选文本点「本地化」立即建条目；已本地化/缺翻译/疑似占位直接编辑原文/译文，自动备份写回。
- **Excel 流程**：导出七 sheet（首表为引擎同算法 `open-yami` 格式），翻译填好后导入回工程，幂等安全。

富文本标签（`<color>`、`<global>`、`<ref>`、`<image>`）解析成实际内容显示；语言列由 `Data/config.json` 驱动，扩展语言无需改工具。

## 性能分析台

只分析打包游戏或 Open Yami 试玩窗口在 **Electron 真机环境**中产生的报告，不再在网页 iframe 中模拟运行游戏：

- CPU / GC / 长帧：导入 Electron 内置 Chromium DevTools 的 Performance trace JSON；
- WebGL：导入现成开源扩展 [Spector.js](https://github.com/BabylonJS/Spector.js) 的 capture JSON；
- 逐帧定位：粘贴工具页提供的「真机探针」到 Electron DevTools 控制台，游玩后导出 JSON，分析哪段更新器/渲染器/事件最常把帧顶超 16.7ms；
- 分析：主线程长任务、帧间隔 P95、GC 占用、CPU 热点、Draw Call、GL 命令、冗余状态和帧资源内存；
- 回归：保存当前摘要为本机基线，后续报告自动显示差值；
- 安全：报告全程在浏览器本地解析，不上传、不运行游戏、不读写工程。

Spector.js 使用上游原版扩展（MIT），本仓库不维护自研采集插件。详细采集步骤见 `tools/perf-lab/README.md`。

## 安全机制（所有写回工具通用）

- 工程目录句柄保存在浏览器本地（IndexedDB），下次打开自动加载或一键重新授权。
- **所有写回前自动备份**到工程根目录 `Lootsmith Backups/<时间戳>/`：
  - 角色编辑器/快速本地化：备份 + 回读校验 + 失败回滚，顶栏「备份与还原」面板可查看/还原/删除。
  - 存档台：写回前备份原存档文件，不触碰引擎自己的 `.bak`。
- 备份目录名不会被 Yami 引擎当成游戏资源扫描。
- 不支持 File System Access API 的浏览器自动进入只读导入模式，保存只下载修改副本，绝不覆盖工程文件。

## 工程自动同步

角色编辑器、地图编辑器、挂机验证台、快速本地化、存档台都会监听工程文件变化：

- 优先 `FileSystemObserver`（Chrome 133+）即时触发；不支持时回退 5 秒轮询（页面切后台暂停）。
- 角色编辑器有未保存草稿时不自动刷新；快速本地化检测到变化只提示、不打断编辑；存档台在游戏内存档后自动重新读取（编辑模式暂停）。

## 常见问题（FAQ）

**Q：为什么我的存档列表是空的？**
检查选择的文件夹是不是工程根目录（要有 `Data` 和 `Save` 子目录）；老工程可能没有 Save 目录（没存过档）。

**Q：改了存档，游戏里没变化？**
① 游戏还开着——它的下次保存会覆盖你的修改，先关游戏再改；② 改完没读档——需要重新读档/重启游戏；③ 改坏了 JSON——保存前有语法校验，读档失败时引擎会自动回退 `.bak`。

**Q：为什么有些 GUID 没有翻译成中文？**
翻译数据来自工程自己的文件（manifest/attribute/variables 等）。资产文件被删、或者 manifest 还没更新（编辑器没重扫）时就会缺；不影响查看。

**Q：存档里 `save00.json` 是什么？**
插件（Excel操作改2「保存json到存档」）写的旁路数据，与引擎存档（`.save`/`.meta`）无关。

**Q：怎么让新电脑/别人也能用这些工具？**
工具本体在浏览器跑，把仓库 clone 下来开个静态服务器即可；工程位置只存在你本机浏览器里，别人需要自己选一次工程。

**Q：工具会修改我的游戏文件吗？**
只有你主动点「保存」才会写回，且写回前一定备份。查看、映射、搜索都是纯读取。
