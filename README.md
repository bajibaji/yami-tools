纯静态 Web 工具合集，所有工程文件均在浏览器本地读取和处理。

## 工具

- **角色编辑器**：编辑角色掉落、掉落事件和人物属性，保存前自动备份。
- **地图编辑器**：导入 Excel / JSON，编辑 10×10 地图格、通行关系、等级和刷怪池。
- **挂机验证台**：读取角色、地图和掉落数据，按游戏实际数值模型模拟单关战斗、全图节奏、长期成长和 A/B 数值方案。

## 挂机验证台

验证台默认提供一套演示地图，也可选择 Yami 工程后读取真实角色与地图 Excel。支持：

- 调整玩家生命、攻击、防御、攻速、技能倍率、命中、暴击和恢复。
- 单独覆盖每关通关击杀数、刷怪等待、赶路时间、金币倍率与目标时间。
- 单独覆盖每个关卡中每种怪物的权重，以及生命、攻击、防御、经验、金币倍率。
- 固定随机种子的重复战斗模拟、10×10 热力图和瓶颈列表。
- 按地图通行关系推演挂机、攒资源、购买升级和解锁关卡的时间线。
- 保存 A/B 快照，比较通关时间、生存率和每小时收益。
- 导入、导出完整验证方案；验证参数不会写回游戏工程。

验证模型对齐游戏实际数值（2026-08-12 从 `D:\new-game` 源码推理）：怪物每级线性成长、`attackTime × attackSpeed + 攻击速度基准 × 10` 的攻击间隔、`(基础命中 + 命中 − 闪避) / 命中骰子` 的阈值命中、同场多怪围攻、死亡即本轮结束。它用于快速筛查节奏与数量级，最终结果仍应以游戏内实测校准。

## 使用

1. 用支持 File System Access API 的浏览器打开 `index.html`（Chrome / Edge / Yami 编辑器内置 Chromium），再选择需要的工具。
2. 点击“选择工程”，选择包含 `Assets`、`Data` 的游戏工程根目录。
3. 工具会递归扫描 `.actor`、`.item`、`.equip` 文件，并从 `Data/attribute.json` 读取属性名称映射。
4. 同时读取 `Data/localization.json`，将 `<ref:本地化ID>` 解析为中文名称；角色头像、物品图标和装备图标按资源 `portrait` / `icon` 与 `clip` 自动裁切预览。
5. 选中角色，在右侧选择物品或装备、填写数量，点击“插入掉落物”。角色列表、掉落列表和资源列表均有独立滚动区域。
6. 点击“保存当前角色”或“保存全部更改”后才会把数组 JSON 字符串写入角色的 `loopList` 属性。

## 安全机制

- 首次选择工程后会把目录句柄保存在浏览器本地。下次打开工具，若浏览器权限仍有效会自动加载；否则点击“加载上次工程”重新授权即可。
- 直接写回工程前，先在工程根目录创建 `Lootsmith Backups/<时间戳>/`，以 `.actor.bak` 扩展名备份所有即将修改的角色文件并逐个回读校验；该扩展名不会被 Yami 当成角色资源扫描。备份失败或发现文件被外部修改时，原文件不会写入。
- 批量保存如果中途失败，会用本次备份自动回滚已经写入的角色；无法回滚时保留备份目录供手动恢复。
- 不支持 File System Access API 的浏览器进入导入预览模式，保存只下载修改副本，不覆盖工程文件。

## 写回格式

属性模式下新建或标准化的掉落列表字符串格式为：

```json
[{"type":"item","id":"物品GUID","min":1,"max":3,"dropRate":0.04},{"type":"equipment","id":"装备GUID","min":1,"max":1,"dropRate":1}]
```

工具优先更新角色根对象的 `loopList`；否则更新 `attributes` 中 ID 为 `4cb407bd71929620`（或属性键为 `loopList`）的字符串；如果不存在则创建该属性。

## 掉落参数与写入模式

- 物品：支持固定数量（`min=max`）或数量范围（`min` 到 `max`）。
- 装备：插件实际按单件装备处理，网页固定写入 `min=1`、`max=1`，不会伪造装备数量。
- 掉落几率：网页使用百分比，例如 `4%`，保存为 `dropRate: 0.04`；`100%` 保存为 `dropRate: 1`。
- **属性字符串**：写入 `loopList`，保留便于其他逻辑读取的列表模式。
- **角色事件**：写入角色的“掉落物品”角色事件（当前工程事件类型 ID 为 `c2ba6c4f90edd668`），仅替换掉落物品插件指令，保留同一事件内的其他指令、启用状态和未知参数。角色没有本地掉落事件时按空列表显示，编辑保存时在角色本地**新建空掉落事件**；不读取、不修改父角色/通用模板的掉落事件。
- 角色事件模式下，每条掉落物右侧都有禁用开关；禁用后保存为 `!249c9c9d4de177c9`，启用后保存为 `249c9c9d4de177c9`，不会删除掉落配置。

如果浏览器不支持直接写入文件夹，工具会自动切换为只读导入模式，保存时下载修改后的 `.actor` 文件。

## 人物属性编辑模式

- 默认打开的是掉落编辑器。人物属性模式**必须手动点击**“人物属性编辑”按钮进入，且不会记住上次模式：刷新、重新扫描后仍回到掉落编辑。
- 进入后展示当前角色的 `attributes` 数组：本地属性可编辑，继承属性只读并显示来源，可“创建本地覆盖”（只写当前角色，绝不修改父角色文件）。
- 支持四种类型：`number`（允许 0、负数和小数）、`boolean`（写回真布尔值）、`string`（保留原始文本，`<ref:...>` 本地化引用不会被自动替换）、`enum`（下拉选择，写回的是枚举项 ID，不是 `value`）。
- 可从 `Data/attribute.json` 的角色属性定义中添加当前角色尚未拥有的属性；已继承但无本地值的属性会变成“创建本地覆盖”。
- 未知属性（定义中不存在）会原样显示和保留，不会被隐藏或删除；删除未知属性需要二次确认。未知枚举值也会保留，不会被静默替换成第一项。
- `loopList` 在人物属性编辑器中只读，由掉落编辑器统一管理，防止两份草稿互相覆盖。
- 所有修改先进草稿，只有点击“保存当前角色”或“保存全部更改”才写回，写回前仍然创建并校验备份；保存顺序固定为人物属性 → loopList → 角色事件，重建 `attributes` 数组后会重新定位 loopList 槽位，不会写错位置。
- 注意：修改人物属性可能影响战斗、AI 与旧存档兼容性，保存前请确认。
